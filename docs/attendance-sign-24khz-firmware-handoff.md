## 新音频规格

| 项目 | 要求 |
| --- | --- |
| 容器 / 编码 | RIFF WAVE，PCM format tag 1，signed 16-bit little-endian |
| 采样率 / 声道 | 24000 Hz，单声道 |
| 帧与数据速率 | 每帧2字节，48000字节/秒 |
| 最长时长 / PCM帧数 | 5秒，最多120000帧 |
| PCM data上限 | 240000字节 |
| 完整WAV下载上限 | **262144字节（256 KiB）**，包含头部和其他合法RIFF块 |

典型44字节头部的5秒文件约240044字节。不能保留原192000字节完整文件上限，也不能继续用80000帧作为24k的5秒限制。

## 固件需要调整的内容

1. **定位旧限制。** 检查音频接收、WAV解析、播放及BSP中的 `16000`、`80000`、`192000`、采样率枚举、缓冲长度和超时；按用途修改，不要全工程替换这些数字。麦克风采集及内置提示音可能有自己的16k设置。
2. **正确解析WAV。** 从 `fmt ` / `data` 块读取真实采样率和数据长度，扫描RIFF块并处理奇数字节填充，不固定假设PCM一定从第44字节开始。新音频校验PCM16、mono、24000Hz、blockAlign=2、byteRate=48000，时长按 `data_bytes / (sample_rate * channels * bytes_per_sample)` 计算，拒绝截断及超过5秒的文件。迁移期间允许原16k mono PCM16旧文件，仍按真实采样率播放；其他格式走现有失败提示。
3. **真实配置播放时钟。** 把从WAV头读到的采样率传给现有ES8311及I2S播放配置，24k文件使用24000Hz。仅放宽解析校验、仅修改WAV头部，或者仍用16000Hz时钟播放24k数据，都会造成速度、音调和时长错误。沿用目标BSP的时钟/MCLK配置，确认其ES8311系数表支持24k；如内部必须使用双声道I2S slot，按现有正确方式复制单声道样本，不改变有效采样帧率。
4. **提示音也要对应。** 每次播放都按资源真实采样率配置；若内置短提示音是16k，在播放它时切回16k，再播放24k人声时切到24k，避免提示音或下一段人声变速。关闭/重配I2S和音频写入要使用现有播放线程的串行流程。
5. **调整下载与缓冲。** 完整WAV接收上限为256KiB，保留PSRAM使用方式；Content-Length存在时先检查，流式/分块接收也要累计检查上限。网络收包缓冲不必一次扩大到256KiB。播放队列继续存事件和URL，复用当前播放缓冲，不为20条待播事件各预留一份256KiB。根据新字节速率核对已有下载和播放超时。
6. **缓存与协议。** 音频SHA256随重新合成自动变化，继续以asset_id区分缓存。接口仍是v1，无新增请求字段；重启/重连基线、去重、排队、5秒显示及短提示音降级逻辑沿用。

ES8311的24k配置可参考 [Espressif官方驱动](https://github.com/espressif/esp-adf/blob/release/v2.x/components/esp_codec_dev/device/es8311/es8311.c)；目标板资源见 [微雪文档](https://docs.waveshare.net/ESP32-S3-RLCD-4.2/)。沿用本机目标工程现有驱动接口，不直接把其他框架版本的代码粘进去。
