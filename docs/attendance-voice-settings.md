# 考勤语音设置

管理员页面：[考勤语音设置](https://erphr.toiroworld.com/desk/attendance-voice-settings)。需要登录具有 **HR Manager** 或 **System Manager** 角色的后台账号。

## 使用方法

1. 先在“正在调整的声音”选择男声、女声或默认声音。各组独立设置音色、语速、音高与抑扬。然后选择“VOICEVOX · 角色音色”或“Nemo · 通用音色”，点击“加载音色”，再选角色、风格和参数。首次唤醒引擎需要几秒时间。
2. 搜索员工，在“姓氏读音（假名）”中只填姓的日语假名，例如王小明填 `ワン`。不填名字或 `さん`，页面仍显示完整姓名。留空时采用“自动姓氏”列，优先使用员工资料中的姓；自动推断不准确时直接填假名覆盖。
3. 需要个人专属音色时，把员工行的“声音配置”改为“专属声音”。上方会自动切到“专属 · 员工姓名”，初始复制该员工当前声音组，再独立调整角色、风格、语速、音高和抑扬。以后点击该员工的“编辑专属声音”，或在上方选择器中切换即可。调整声音组不会覆盖已经启用的专属参数；需要恢复时把员工行改回“自动”或具体声音组。
4. 展开员工读音下方的“自定义出勤 / 退勤”，分别填写完整朗读内容，例如出勤 `おはよう、ワンさん。`、退勤 `また明日、ワンさん。`。填写后原样朗读，不再自动追加姓氏、“さん”或固定问候；每项留空可独立恢复默认。每项最多120字单行文字，每段音频仍需在5秒内。普通声音组也能使用自定义语句，无需先启用专属音色。
5. 点击员工旁的“试听签到”或“试听签退”。试听使用当前文字，无需先保存；播放器也可以重播。优先使用员工专属音色，其次是手动指定的男声/女声/默认组，最后按员工资料自动分组；其他或未填写性别使用默认声音。试听始终使用该员工实际适用的声音，与上方当前编辑对象无关。
6. 点击“保存草稿”保存进度；以后重新打开页面可以继续编辑。
7. **只改一位员工时**，点击该行“仅生成本人”。页面会自动保存草稿，只生成本人的签到、签退两段；完成后点击该行“发布本人”，或上方明确写有员工姓名的发布按钮。发布只替换本人的两段语音，其他员工的音频和映射保留，其他人的草稿修改也不会随之发布。
8. 需要统一更换一组或全体声音时，继续使用上方“生成全员语音”，完成后单独“发布到签到牌”。当前一次处理一个生成任务，任务区域会显示员工姓名或全员范围。已支持24k的签到牌无需因这项功能升级固件；尚未升级的板子先按[固件调整说明](attendance-sign-24khz-firmware-handoff.md)完成播放及缓冲调整，再发布。

自定义项留空时，出勤默认 `ワンさん、おはようございます。`，退勤默认 `ワンさん、お疲れさまでした。`，其中姓氏使用员工自己的假名读音或自动姓氏。试听与新生成统一24kHz、PCM16、单声道，完整WAV上限256KiB。每段最多5秒；如超长，请提高语速或缩短朗读内容。

本人实际音色、朗读语句或姓名变化后，应重新生成本人语音再发布；其他员工的修改不影响这位员工的待发布结果。全员任务仍要求整个草稿及员工资料与生成时一致。生成失败不会替换当前已发布的音频；页面保留输入，可修改后重试。另一个窗口修改了草稿时会提示刷新，避免互相覆盖。

抑扬控制语调起伏：0更平直，1为自然默认，2起伏更明显。音高控制整体声音的高低，0保留原始音高、负数更低沉、正数更高，页面支持-0.15～0.15。声音组及每个专属配置都能独立调整，实际通过[VOICEVOX的intonationScale与pitchScale参数](https://github.com/VOICEVOX/voicevox_engine/blob/master/voicevox_engine/model.py)合成。

声音来源会显示在音色选择和试听区域，并记录在发布清单。混合发布时清单分别保存每个实际使用组及每位专属员工的参数与署名，设备旁应对应标注所有实际使用的声音。普通角色音色示例为 `VOICEVOX:四国めたん`，Nemo 为 `VOICEVOX Nemo`。更换角色后，设备旁的声音署名也应对应更换。

## 服务器部署

页面是 Frappe Desk Page，无需构建 PWA，也没有数据库字段迁移。在应用代码部署后，从正式 bench 容器执行：

```bash
bench --site hrms.localhost reload-doc hr page attendance_voice_settings
bench --site hrms.localhost clear-cache
```

后台生成使用现有 `default` 队列，任务超时 600 秒。`attendance_voice_queue` 仅供隔离测试站点覆盖队列；自定义队列必须同时配置并启动对应 worker。

宿主服务通过固定 Compose 文件管理引擎；Web 容器没有 Docker socket。本站安装路径已写入 [用户服务模板](../deploy/hrms-attendance-voice-engines.service)，在服务器主机以 `uo` 用户执行：

```bash
mkdir -p ~/.config/systemd/user
cp deploy/hrms-attendance-voice-engines.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now hrms-attendance-voice-engines.service
systemctl --user status hrms-attendance-voice-engines.service
```

用户服务应配置开机驻留（本站 `uo` 已启用 linger）。部署到其他路径时修改模板中的路径；Docker 网络默认 `docker_default`，可通过服务的 `NEMO_NETWORK` 环境变量覆盖。

两种引擎均优先 GPU，只有加载音色、试听或生成时启动；空闲 60 秒停止并释放模型占用。小型租约管理进程常驻，预生成音频一直保留，日常打卡不启动 TTS。NVIDIA runtime 不可用时，可停止该服务，给 `ExecStart` 添加 `--cpu` 后重新加载并启动；CPU 与 GPU 模式不可同时运行。

查看运行情况：

```bash
journalctl --user -u hrms-attendance-voice-engines.service -n 50 --no-pager
docker compose -f deploy/attendance-voice.compose.yaml --profile gpu ps -a
```

草稿、预览和待发布资源位于 `sites/hrms.localhost/private/attendance-voice-settings/`；正式资源仍位于 `private/attendance-sign/`，设备接口保持 v1。备份这两个私有目录即可保留设置与发布内容，不要把员工读音或站点凭据提交到 Git。

2026-10-17 上线管理页时保留原正式发布内容，不自动替换全名语音。用户在页面填写姓氏假名、试听满意后，自行生成和发布首个姓氏版本。
