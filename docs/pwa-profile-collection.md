# PWA 员工资料收集

入口：PWA 首页或个人页的「完善个人资料」。直接地址为 `/hrms/profile/complete`。

当前已向所有在职员工开放。账号必须已启用，且绑定状态为 Active 的员工档案；员工只能读取和提交本人资料，HR／管理员的全员信息总表权限保持原有范围。

## 员工使用

姓名和员工编号为只读。手机号、现住址、联系邮箱以及紧急联系人姓名、亲属、紧急联系电话均为必填，微信号选填。紧急联系人单独分区，亲属可填写父母、配偶、子女等，联系电话支持国家区号。页面预填已有资料；邮箱优先使用公司邮箱、个人邮箱、关联登录账号邮箱。

点击「确认并提交」后直接更新原来的 Employee 档案。成功页面显示提交结果，可返回首页或再次修改。HR 在员工信息总表刷新后即可看到最新资料，无需复制、审批或新建员工。

联系邮箱更新到员工正在使用的公司邮箱字段；公司邮箱原本为空时，写入个人邮箱。登录账号不变。

提交失败时保留输入。资料被 HR 等其他人更新过时，提示重新读取，避免覆盖新资料。此功能不影响打卡，不增加强制弹窗或期限。

## 开放范围

正式站点配置：

```json
{"pwa_profile_collection_enabled": true, "pwa_profile_collection_users": []}
```

全员开关开启时，所有绑定已启用账号的在职员工均可使用，新入职员工绑定账号后自动可用。离职、停用、未绑定员工的账号和访客均不可用。尚未绑定登录账号的在职员工需要先绑定账号。

关闭全员开关时，退回 `pwa_profile_collection_users` 明确名单试用；两者均关闭／为空时，不开放给任何人。每次读取和保存都会重新核验开放范围、账号有效性和在职状态。已登录的员工刷新或重新打开 PWA 后可看到入口。

## 权限与验证

`hrms.api.employee_profile` 只公开当前会话用户的七项联系资料及必要的身份展示、版本信息。保存只接受这七项和 `modified`，不能指定其他员工或修改账号、状态、银行资料。受限接口使用 Employee 的正常保存和并发校验，不增加员工的通用写权限。

后端测试：`hrms.tests.test_employee_profile_collection`；前端测试：`frontend/src/utils/profileCollection.test.js`、`frontend/src/components/profile/ProfileCollectionForm.test.js`。在独立测试站点验证提交流程和 HR 总表同步；正式站点仅核验访问范围，不代员工填写真实资料。
